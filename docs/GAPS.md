## 3. Accepted limitations

Items promoted from sections 1–2 that we decided to live with. Each becomes
a bullet in the README's Known Limitations.

| ID | Limitation | Why accepted |
|---|---|---|
| V5 | A line that is not valid JSON (for example truncated) is ingested as **one all-null row**: every column is null, including `_rescued_data`, so the broken text is lost, and the run still succeeds with no warning. Observed 2026-09-24 with a one-line probe file (Bronze grew by exactly 1 row; the row was then deleted) | Bronze stays append-only and complete. The verify query's `null_times` check (expected 0) flags such rows. Silver will drop or quarantine rows with a null `transaction_id`. Capturing the raw text in a corrupt-record column is possible in principle but untested |
